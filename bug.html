1. Profil Arsitektur & Infrastruktur Sistem Hasil Rekayasa Balik Runtime

Frontend & Edge Runtime
TanStack Start • Cloudflare Workers

Aplikasi berbasis SSR (TanStack Router + Start) yang dijalankan pada jaringan Cloudflare Workers melalui platform Lovable Cloud (IP Anycast: 185.158.133.1). Seluruh eksekusi data diarahkan melalui endpoint internal /_serverFn/.

Database & Data Layer
Supabase PostgreSQL (AWS Cloud)

Basis data dikelola pada instans Supabase (jpmfsldnzptdgfhvdqpb.supabase.co) dengan PostgREST API dan Row Level Security (RLS).

Penyimpanan Media (Object Storage)
Cloudflare R2 Bucket

Berkas statis publik dan video materi disimpan pada bucket Cloudflare R2 publik (pub-bb2e103a32db4e198524a2e9ed8f35b4.r2.dev).

Struktur Multi-Tenancy
DigiAksi White-Label Cluster

Platform berjalan sebagai sub-tenant (/?tenant=belajarplus.id) pada klaster SaaS multi-tenant DigiAksi (terlihat dari kunci cart aksi.cart.v2 dan manifest PWA).

Analisis Akar Masalah (Root Cause): Mayoritas anomali batas (*edge cases*), data rekening kosong, dan celah integritas pengacakan berakar dari sifat pembuatan kode otomatis (*AI code generation*) yang mengasumsikan alur selalu ideal (*happy-path bias*), serta minimnya pengujian batas (*boundary & defensive programming*) sebelum rilis ke produksi.

BUG-001

Nomor Rekening Bank Ditampilkan Strip (—) pada Rincian Transfer Manual

P0 - Kritis Bug Sistem
Modul: Toko & Pembayaran (`/orders`, `/checkout`) Dampak Peran: Siswa, Orang Tua / Wali Murid Status: Terverifikasi di Produksi
A. Deskripsi Masalah & Dampak Teknis

Ketika siswa/orang tua memilih buku dan melakukan checkout metode Transfer Bank Manual, kartu detail pesanan memuat rincian nominal dan nomor pesanan, tetapi kolom nama bank dan nomor rekening tujuan hanya menampilkan tanda strip (—). Akibatnya, orang tua tidak dapat mentransfer uang dan pesanan buku tertahan tanpa ada kejelasan kontak.

Bukti Forensik Database Supabase:
Investigasi langsung ke backend Supabase production (jpmfsldnzptdgfhvdqpb.supabase.co) mengungkap akar masalahnya: pemanggilan API PostgREST ke tabel public.payment_settings mengembalikan array kosong [] (Zero Rows). Pengembang tidak melakukan initial database seeding data rekening atau policy Row Level Security (RLS) SELECT belum diberikan izin baca ke publik/anon role.

B. Bukti Analisis Kode & Respon API
  1. Buka menu /shop, pilih varian buku (misal Cetak atau Digital), masukkan keranjang.
  2. Lanjutkan checkout hingga tahap konfirmasi pesanan (`/orders/[id]`).
  3. Amati kartu "Informasi Rekening Pembayaran": Field Rekening hanya berisi teks strip (—).
  4. Verifikasi forensik via PostgREST endpoint:
    curl -s -H "apikey: sb_publishable_..." "https://jpmfsldnzptdgfhvdqpb.supabase.co/rest/v1/payment_settings?select=*"
    Response: [] (Array Kosong / Seed Data Belum Dimasukkan)
C. Langkah Reproduksi
  1. Buka menu /shop, pilih varian buku (misal Cetak atau Digital), masukkan keranjang.
  2. Lanjutkan checkout hingga tahap konfirmasi pesanan (`/orders/[id]`).
  3. Amati kartu "Informasi Rekening Pembayaran": Field Rekening hanya berisi teks strip (—).
  4. Verifikasi forensik via PostgREST endpoint:
    curl -s -H "apikey: sb_publishable_..." "https://jpmfsldnzptdgfhvdqpb.supabase.co/rest/v1/payment_settings?select=*"
    Response: [] (Array Kosong / Seed Data Belum Dimasukkan)
D. Rekomendasi Solusi Teknis
  1. Lakukan seeding baris default ke tabel public.payment_settings (misal: bank_name, account_number, account_holder).
  2. Periksa policy RLS Supabase: pastikan ada rule CREATE POLICY "Allow public read payment settings" ON public.payment_settings FOR SELECT USING (true);.
  3. Pada frontend TanStack Start, pasang guard clause: sembunyikan opsi Transfer Manual jika tabel payment_settings kosong atau tampilkan banner darurat nomor WhatsApp bendahara.

BUG-002

Infinite Loading Spinner saat Menjalankan Ujian dengan 0 Soal

P0 - Kritis Bug Sistem
Modul: Ujian LJD & Ruang Kelas (`/classes/[id]/assignment`) Dampak Peran: Siswa Status: Terverifikasi di Produksi
A. Deskripsi Masalah & Dampak Teknis

Jika seorang guru mempublikasikan penugasan/ujian LJD yang bank soalnya masih kosong (0 butir soal), siswa yang mengklik tombol "Kerjakan" akan mengalami infinite loading. Halaman hanya menampilkan spinner berputar terus-menerus tanpa batas waktu (timeout) dan tidak ada tombol kembali, memaksa siswa menutup paksa browser.

C. Langkah Reproduksi
  1. Guru membuat paket tugas tanpa menginput butir soal.
  2. Siswa masuk ke tab Penugasan kelas dan klik tombol "Kerjakan".
  3. Layar memuat `ljd_engine` dan berputar tanpa henti tanpa memunculkan pesan error.
D. Rekomendasi Solusi Teknis
Tambahkan guard clause pada komponen controller LJD: jika respon API `questions.length === 0`, hentikan spinner dan munculkan modal dialog informatif: "Paket soal belum diisi oleh pengajar. Silakan konfirmasi ke guru Anda." sertakan tombol kembali ke dashboard.

BUG-004

Indikator Pelanggaran Anti-Cheat Melampaui Batas Toleransi Tanpa Konsekuensi Eksplisit

P1 - Tinggi Bug Sistem
Modul: Ujian LJD Antarmuka Siswa Dampak Peran: Siswa Status: Terverifikasi di Produksi
A. Deskripsi Masalah & Dampak Teknis

Sistem pengawas anti-cheat BelajarPlus menampilkan indikator pelanggaran di header atas dengan format rasio (contoh: Pelanggaran 8/3). Secara logika, angka 3 adalah batas maksimal toleransi. Namun sistem membiarkan angka menembus hingga 8 tanpa auto-submit atau warning dialog yang jelas, membuat siswa bingung apakah status ujiannya sah atau sudah didiskualifikasi.

C. Langkah Reproduksi
  1. Buka ujian LJD yang memiliki proteksi tab focus aktif.
  2. Pindah tab atau buka aplikasi lain beberapa kali.
  3. Counter pelanggaran terus bertambah melampaui denominator (contoh: 8/3) tanpa interupsi sistem.
D. Rekomendasi Solusi Teknis
Terapkan batas tegas (*hard cap*). Pada pelanggaran ke-1 dan ke-2, tampilkan modal peringatan interupsi layar. Jika menyentuh 3/3, jalankan fungsi `submitExamImmediately()` dengan status catatan *“Selesai otomatis: Melebihi batas pelanggaran pengawas”*.

BUG-011

Ketiadaan Validasi Client-Side Format & Ukuran File Bukti Pembayaran

P2 - Sedang Bug Sistem
Modul: Upload Bukti Struk Transfer (`/orders/[id]`) Dampak Peran: Siswa, Orang Tua Status: Terverifikasi di Produksi
A. Deskripsi Masalah & Dampak Teknis

Form unggah bukti transfer manual di halaman detail pesanan tidak membatasi ekstensi file pada tag input (`accept`) dan tidak memverifikasi ukuran berkas sebelum tombol diklik. Pengguna HP yang memotret struk dengan resolusi tinggi (> 5 MB) atau format HEIC baru mendapati proses gagal setelah menunggu lama (*HTTP 413 Payload Too Large* atau *Internal Server Error*).

C. Langkah Reproduksi
  1. Buat pesanan transfer manual di Toko.
  2. Pada tombol "Pilih file", pilih file gambar mentah kamera ponsel (> 6 MB).
  3. Klik "Unggah bukti & konfirmasi". Tidak ada pesan validasi instan, request langsung macet/gagal.
D. Rekomendasi Solusi Teknis
Tambahkan atribut `accept=".jpg,.jpeg,.png,.pdf"` dan lakukan kompresi otomatis di sisi browser (via Canvas API) atau tolak langsung berkas jika melebihi 5 MB sebelum request `multipart/form-data` dikirimkan ke server.
