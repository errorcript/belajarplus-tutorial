Profil Arsitektur Sistem BelajarPlus.id

Hasil rekayasa balik (reverse-engineering) dan inspeksi runtime terhadap infrastruktur, framework, dan data layer yang mendasari platform.

⚡ Platform & Code Generator
Lovable.app (AI Fullstack)

Seluruh basis kode front-end di-generate menggunakan AI prompt builder Lovable. Terverifikasi dari asset bundle dan referensi OpenGraph image yang mengarah langsung ke bucket preview Lovable (id-preview-*.lovable.app).

⚛️ Frontend Framework
TanStack Start + React 18/19

Menggunakan fullstack SSR routing berbasis TanStack Start & TanStack Router (bundling __tsr chunk). Menangani file-based route seperti /dashboard, /orders/$id, dan /settings.

🔄 State & Cache Layer
TanStack Query (React Query)

Pengelolaan remote state, cache invalidation, dan query re-fetching saat mutasi data dilakukan melalui asynchronous query client.

🗄️ Backend & Database
Supabase (PostgreSQL + PostgREST)

BaaS berbasis PostgreSQL dengan Row-Level Security (RLS), autodelegasi API PostgREST via client JWT token, serta Realtime WebSockets untuk event listener notifikasi live.

☁️ Edge Hosting & Storage
Cloudflare Workers + R2 Storage

Deployment server edge dijalankan di atas Cloudflare Workers, sementara aset statis, preview, dan file upload ditampung di Cloudflare R2 Object Storage (*.r2.dev).

🎨 UI System & Primitives
Tailwind CSS + Shadcn / Radix UI

Komponen UI headless dari Radix UI (Dialog, Dropdown, Accordion) yang dibungkus dengan Tailwind CSS utilities khas ekosistem Shadcn UI.

🏢 Induk Platform & Whitelabel
DigiAksi (digiaksi.id)

BelajarPlus merupakan multi-tenant / whitelabel dari platform DigiAksi. Terbukti dari placeholder email peringatan admin (admin@digiaksi.id), route pohon ujian, dan backend scoring worker yang identik.

🌐 Domain Registrar vs Server Real
IDwebhost (.id) & Name.com (.com)

Domain .id dibeli via IDwebhost (NS: ns1.idwebhost.id) dan .com via Name.com. Namun, di IDwebhost hanya DNS A-Record yang diarahkan ke luar (tidak ada hosting cPanel / web server di sana). Server aplikasi sebenarnya 100% serverless di-host pada Lovable Cloud / Cloudflare Edge (185.158.133.1).

🗄️ Database Cloud Instance
Supabase (AWS Cloud Managed)

Instance database PostgreSQL beralamat di https://jpmfsldnzptdgfhvdqpb.supabase.co (AWS us-east / Cloudflare proxy), terintegrasi langsung dengan PostgREST API client-side JWT token.

🏢 Multi-Tenant SaaS Cluster
DigiAksi White-Label Engine

BelajarPlus berjalan sebagai sub-tenant (/?tenant=belajarplus.id) pada klaster SaaS multi-tenant DigiAksi (terlihat dari kunci cart aksi.cart.v2, fallback alert admin@digiaksi.id, dan manifest dynamic injection).

BUG-001

Nomor Rekening Bank Ditampilkan Strip (—) pada Rincian Transfer Manual

🐛 System Bug P0 - Blocker
Modul: Toko & Pembayaran (`/orders`, `/checkout`) Peran Terkena: Siswa, Orang Tua / Wali Murid Status: Terkonfirmasi di Production
⚠️ Deskripsi Gejala & Dampak:

Ketika siswa/orang tua memilih buku dan melakukan checkout metode Transfer Bank Manual, kartu detail pesanan memuat rincian nominal dan nomor pesanan, tetapi kolom nama bank dan nomor rekening tujuan hanya menampilkan tanda strip (—). Akibatnya, orang tua tidak dapat mentransfer uang dan pesanan buku tertahan tanpa ada kejelasan kontak.

🔬 Bukti Forensik Database Supabase:
Investigasi langsung ke backend Supabase production (jpmfsldnzptdgfhvdqpb.supabase.co) mengungkap akar masalahnya: pemanggilan API PostgREST ke tabel public.payment_settings mengembalikan array kosong [] (Zero Rows). Pengembang tidak melakukan initial database seeding data rekening atau policy Row Level Security (RLS) SELECT belum diberikan izin baca ke publik/anon role.

🔁 Langkah Reproduksi & Verifikasi API:
  1. Buka menu /shop, pilih varian buku (misal Cetak atau Digital), masukkan keranjang.
  2. Lanjutkan checkout hingga tahap konfirmasi pesanan (`/orders/[id]`).
  3. Amati kartu "Informasi Rekening Pembayaran": Field Rekening hanya berisi teks strip (—).
  4. Verifikasi forensik via PostgREST endpoint:
    curl -s -H "apikey: sb_publishable_..." "https://jpmfsldnzptdgfhvdqpb.supabase.co/rest/v1/payment_settings?select=*"
    Response: [] (Array Kosong / Seed Data Belum Dimasukkan)
💡 Rekomendasi Solusi Teknis:
  1. Lakukan seeding baris default ke tabel public.payment_settings (misal: bank_name, account_number, account_holder).
  2. Periksa policy RLS Supabase: pastikan ada rule CREATE POLICY "Allow public read payment settings" ON public.payment_settings FOR SELECT USING (true);.
  3. Pada frontend TanStack Start, pasang guard clause: sembunyikan opsi Transfer Manual jika tabel payment_settings kosong atau tampilkan banner darurat nomor WhatsApp bendahara.

BUG-004

Indikator Pelanggaran Anti-Cheat Melampaui Batas Toleransi Tanpa Konsekuensi Eksplisit

🐛 System Bug P1 - High
Modul: Ujian LJD Antarmuka Siswa Peran Terkena: Siswa Status: Terkonfirmasi di Production
⚠️ Deskripsi Gejala & Dampak:

Sistem pengawas anti-cheat BelajarPlus menampilkan indikator pelanggaran di header atas dengan format rasio (contoh: Pelanggaran 8/3). Secara logika, angka 3 adalah batas maksimal toleransi. Namun sistem membiarkan angka menembus hingga 8 tanpa auto-submit atau warning dialog yang jelas, membuat siswa bingung apakah status ujiannya sah atau sudah didiskualifikasi.

🔁 Langkah Reproduksi (Steps to Reproduce):
  1. Buka ujian LJD yang memiliki proteksi tab focus aktif.
  2. Pindah tab atau buka aplikasi lain beberapa kali.
  3. Counter pelanggaran terus bertambah melampaui denominator (contoh: 8/3) tanpa interupsi sistem.
💡 Rekomendasi Solusi Teknis: Terapkan batas tegas (*hard cap*). Pada pelanggaran ke-1 dan ke-2, tampilkan modal peringatan interupsi layar. Jika menyentuh 3/3, jalankan fungsi `submitExamImmediately()` dengan status catatan *“Selesai otomatis: Melebihi batas pelanggaran pengawas”*.
